# NovelMatch 产品决策记录

本文记录 V1.0 中几个关键产品取舍，便于说明「为什么这样做」，而不是只展示功能。

---

## 1. 用个人匹配度替代大众评分

**问题**

传统小说评分是人群平均值，无法回答「这本书是否适合我」。同一本书对不同读者的价值可能完全相反。

**决策**

产品不提供统一质量分，而是输出「小说与当前用户画像的匹配度」。

**影响**

- 匹配度不能脱离画像独立存在。
- 报告必须明确「结果仅供参考」，避免让用户误以为是客观概率。
- 后续需要用真实用户反馈校准权重，而不是直接宣传准确率。

---

## 2. 采用正向 + 负向双通道参考样本

**问题**

只有喜欢的小说时，AI 容易把所有高分特征都误认为用户偏好，无法区分「好」和「我喜欢」。

**决策**

- 喜欢的小说：七维度 1–5 星评分。
- 讨厌的小说：只选最差和第二差的两个维度。

**理由**

要求用户给讨厌的小说逐项打低分，负担高且不稳定；「最差 / 第二差」更接近真实的弃书原因，也能形成明确的惩罚信号。

**取舍**

- 负向样本信息量较少，但收集成本低。
- 允许只存在一类样本，但画像必须明确反映证据范围，不能虚构另一类偏好。

---

## 3. 七维度作为内部框架，不在前台展示雷达图

**维度**

文笔、剧情、人物塑造、世界观、节奏、创意、爽点。

**决策**

七维度用于 AI 分析与加权匹配，前台只展示：

- 阅读品味总结
- 偏好关键词
- 喜欢的特征
- 不喜欢的特征

**理由**

用户购买的是「这本书适不适合我」的答案，不是一份复杂的文学分析报告。雷达图会增加理解成本，却不能直接帮助选书。

**取舍**

需要牺牲一部分「分析过程的可解释性」，用自然语言总结和匹配依据补足。

---

## 4. 爽点不预设分类

**决策**

爽点不采用「打脸、升级、扮猪吃虎」等固定标签，而由 AI 从参考样本中归纳用户偏好的情绪反馈和期待兑现方式。

**理由**

不同题材、不同读者的爽点差异很大，固定分类容易把复杂偏好压缩成有限选项。

**风险**

- 归纳结果依赖模型能力。
- 不同模型可能给出不同粒度的爽点描述，需要后续做稳定性评估。

---

## 5. 本地优先，而不是云端账号体系

**决策**

V1.0 不做注册登录和云端同步，画像与评估记录保存在本机 SQLite，API Key 保存在系统凭据管理器。

**理由**

- 阅读偏好属于高隐私数据。
- 目标用户是个人读者，不需要多人协作。
- 本地优先降低后端成本与合规风险。

**取舍**

- 换设备无法同步。
- 数据备份/恢复需要额外设计，V1.0 尚未实现。
- 用户自行承担模型调用费用。

---

## 6. 用户自带模型，而不是统一 AI 网关

**决策**

用户填写 API Key、模型名称和 Base URL，桌面端直接调用 OpenAI Chat Completions 兼容接口。

**理由**

- 不建设中心化 AI 网关，降低运营成本和密钥托管风险。
- 用户可以自由选择服务商和模型，避免绑定单一供应商。

**取舍**

- 首次使用门槛更高。
- 不同模型的 JSON 稳定性不同，需要结构化校验和修复重试。
- 需要向用户明确：正文会发送到其配置的第三方模型服务。

---

## 7. 不做起点反爬绕过

**现象**

起点对非浏览器请求返回：

```text
HTTP 202
probe.js 访问验证页
```

**决策**

不实现验证码破解、Cookie 伪造、无头浏览器绕过。起点暂不纳入自动抓取来源。

**理由**

- 技术规范明确要求不绕过反爬、登录和付费墙。
- 绕过方案不稳定，且存在合规风险。
- 产品价值不应建立在对平台规则的规避上。

**后续方案**

- 官方 API / 合作渠道。
- 用户手动粘贴正文或导入 TXT。
- 优先支持公开静态页面来源。

---

## 8. 匹配度采用 AI 打分 + 后端加权汇总

**决策**

AI 返回七维度匹配分与权重，后端按公式计算最终匹配度，而不是让模型直接给一个总百分比。

**理由**

- 避免模型直接输出一个不可解释的数字。
- 权重可以结合用户评分和负向排序。
- 便于后续做校准与调试。

**限制**

权重与分数仍由模型生成，尚未经过统计验证；V1.0 的匹配度应定位为「模型驱动的匹配估计」。

---

## 9. 画像重新生成采用手动触发

**决策**

用户补充参考小说后，不自动重算画像，而是手动点击「重新生成画像」。

**理由**

- 避免用户在不知情的情况下覆盖已经手动编辑的总结。
- 生成过程耗时且会调用模型，自动触发成本不可控。

**取舍**

画像可能短暂与最新参考样本不同步，因此界面需要明确提示重新生成会覆盖编辑内容。

---

## 10. V1.0 不追求大而全

明确不做：

- macOS / 移动端
- 账号与云端同步
- 社区与分享
- 主动推荐
- 本地大模型
- 多模型任务分配
- 复杂模型参数配置

目标是先跑通「参考样本 → 画像 → 评估 → 报告」的完整闭环。
